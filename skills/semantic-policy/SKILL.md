# Semantic policy loop (optional extension)

Use when the human asks to author/reconcile IR, explain behavior through an IR,
model an observed opponent, or research through semantic edits. The contract is
[Spec 0001](../../docs/specs/0001-semantic-ir-symbolic-loop.md). This skill adds a
workflow; it does not supply a universal compiler, scheduler or game evaluator.

## Resolve scope and capabilities

Read the root/lab working context, stated preferences and experiment/refutation
records. Resolve `semantic-policy` through the active lab's `MIXIN.md` Additional
skills table. Preserve the seed's five required bindings and all existing gates.
Missing optional conversion tooling permits a documented hypothesis or analysis;
it cannot produce a passed compilation/fidelity claim. State the missing
capability precisely and continue the parts the available evidence supports.

Select the artifact kind: our executable policy, inferred opponent, source audit,
or qualified reactive proxy. Read native schemas and actual adapter commands from
the binding. Do not execute the proposed neutral CLI until it is implemented.

## Freeze the subject before changing it

1. Pin exact parent IR/Python/source, game/runtime, binding closure, roster and
   evidence identities. Store originals immutably and verify all dependencies.
2. Resolve selected versus execution-verified policy references. Preserve any
   correction and the superseded analysis. Snapshot coaching inputs, authorship,
   clock mapping, cost/exposure and unresolved interpretation before the cycle.
3. Name one attributable hypothesis. State observations, interpretation,
   alternatives, expected behavior, negative/interruption cases and a prospective
   game-specific verdict. A dependent package must not claim isolated component
   effects. Preserve independent test/holdout ownership.

## Reconcile and check

For our policy, use the binding's declared authoring direction. Import literal
Python as data; compare canonical JSON under its pinned native value profile.
IR edits compile only through recognized operators. Source edits must be fully
accounted for by bounded extraction; unknown/ambiguous code blocks admission.
Preserve uncertainty about semantic goals and invalidate affected claims.

Record representation consistency, semantic fidelity, runtime validity and hosted
performance as separate receipts. Test positive, non-trigger, boundary, memory,
interruption and preservation behavior against independently frozen checks. Never
repair a failed candidate by silently weakening its checker. New verifier results
append an assessment while preserving the original attempt and verdict.

For an episode, resolve all matching/evaluated rules and ordered requests, then
separate acceptance, effective channel state and observed outcome. Preserve gaps,
unknowns and `[unglossed]` behavior. Full source reconstruction proves only its
stated retrospective scope; responsive intervention is an additional capability.

For an opponent, freeze observation authority, exact version, eligibility/features,
trajectory-group split, granularity and baselines before fitting. Keep hidden
truth/source audit separate from observer inputs. Report support, visibility,
censoring, duplicate streams and novel holdout results. Do not promote forecasts
or source audits to reactive rollouts without intervention and closed-loop tests
plus an enforced validity envelope.

## Evaluate and record through the existing loop

Use `experiment`, the lab's evaluation/measurement bindings and `build-upload`
for actual policy tests. Local checks remain debugging evidence; hosted outcomes
are the competitive verdict. Preserve invalid denominators even when quarantining
scores. Record every upload before proceeding. Require a fresh unchanged-artifact
confirmation and the experiment's full opponent/seat criteria for retention claims.

Write one authoritative experiment verdict with linked immutable sidecars; update
current context, version log and refutations in their existing homes. Publish a
complete IR/source revision atomically with a stale-parent check before changing
an incumbent pointer. An unfinished candidate cannot overwrite a usable incumbent.

Passing these checks confers no submission permission. Follow the existing
`submit` skill and recorded human authority. Scheduled/autonomous work additionally
needs scoped authorization, budget, stop conditions, durable journal and single
writer ownership; this optional skill does not widen autonomy by itself.
